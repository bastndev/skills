# Next.js project scaffold

Create the prepared Next.js base from `assets/template/`. Keep its route groups, shared workspace shell, configuration ownership, and theme behavior intact while adapting the visible project name.

## Inputs and boundaries

- Use the current directory as the project root unless the user explicitly supplies another destination. Derive `PROJECT_NAME` from that directory's basename and preserve its visible spelling and casing. Do not ask for a name when one is already available.
- Inspect the destination before writing. Preserve unrelated files, editor settings, agent instructions, and skill-installation metadata. Stop before overwriting user-authored project files; this skill creates a new project, not a migration.
- Treat `assets/template/` as the source of truth. Copy its files rather than recreating or redesigning them from memory.
- Use Bun and keep `bun.lock`. Do not initialize Git, deploy, or add a publishing workflow unless requested.
- Keep the five example routes: Home, Work, Contact, Login, and Register. The `(workspace)` and `(auth)` folders organize layouts without changing URLs. Login and Register are placeholders; do not imply that authentication exists.
- Add APIs, authentication, databases, stores, services, or additional libraries only when the user requests them or the project needs them.

## Procedure

### 1. Create the project

Run in the destination directory:

```bash
bun create next-app@latest . --ts --tailwind --eslint --app --src-dir --import-alias '@/*' --use-bun --no-react-compiler --disable-git --yes
```

This creates the framework-owned package metadata, Bun lockfile, and configuration. Preserve any agent instructions generated by Next.js now or during the first development run. If a flag changes, inspect `bun create next-app@latest --help` and select the equivalent TypeScript, Tailwind CSS, ESLint, App Router, `src/`, Bun, and no-Git setup. Do not silently accept saved CLI preferences that change the requested stack.

If the directory name is rejected or a real file conflict prevents scaffolding, explain the exact blocker instead of renaming the directory, deleting user files, or creating a substitute project elsewhere.

### 2. Apply the bundled template

Resolve the directory containing this `SKILL.md` as `SKILL_DIR`. Before copying, remove only these files when they came from the fresh scaffold:

```text
src/app/page.tsx
public/file.svg
public/globe.svg
public/next.svg
public/window.svg
```

`src/app/page.tsx` must not remain because the bundled `(workspace)/page.tsx` also owns `/`. The unused public SVGs are absent from the prepared base. Stop if any listed path existed before scaffolding or contains user work.

Copy every file, including dotfiles and the binary favicon, into the project root:

```bash
cp -a "$SKILL_DIR/assets/template/." .
```

The bundled `tsconfig.json` deliberately maps `@/*` to `./*`; template imports therefore use paths such as `@/src/components/ui/Header`. Preserve that pairing.

Replace `{{PROJECT_NAME}}` in exactly these files:

- `README.md` — visible project title.
- `src/consts.ts` — `SITE.name`, safely escaped as a TypeScript string.

Confirm the placeholder is gone:

```bash
rg -n '\{\{PROJECT_NAME\}\}' README.md src/consts.ts
```

No matches is the expected result (`rg` exits with status 1).

Keep scaffold-generated `package.json`, `bun.lock`, `.gitignore`, Next.js/PostCSS/ESLint configuration, and agent instructions. The template replaces only its inventoried files.

### 3. Install the direct dependency

```bash
bun add lucide-react
```

Add this script to the generated `package.json` while preserving all generated fields and versions:

```json
{
  "scripts": {
    "typecheck": "next typegen && tsc --noEmit"
  }
}
```

Do not install shadcn/ui or `next-themes`; the prepared template uses a native button, local social SVGs, and its own small `data-theme` implementation.

### 4. Verify the generated project

```bash
bun run lint
bun run typecheck
bun run build
```

Read failures, make focused corrections, and rerun the failed check. Consult the generated `AGENTS.md` and the relevant local Next.js guide under `node_modules/next/dist/docs/` before changing framework code. A dependency, registry, or font-download failure is a blocker, not a passing build.

On an interrupted setup, inspect completed files and resume from the remaining step. Do not rerun initialization over modified files. Run `git diff --check` when the destination is a Git repository.

When a browser is available, preview the generated project and verify:

- `/`, `/work`, `/contact`, `/login`, and `/register` load with the intended title, heading, and layout.
- Main navigation marks the current page and all header links work at mobile and desktop widths.
- The default is dark; valid saved light/dark choices restore before paint; invalid or missing values fall back to dark.
- The toggle still changes the current document when storage is unavailable, persists when storage works, supports Enter and Space, has an accessible name and visible focus, and respects reduced motion.
- The skip link reaches `#main-content`, and the console has no hydration errors or warnings.

Stop any preview started solely for verification. If browser checks cannot be performed, state that separately; a production build does not prove interaction behavior.

## Architecture guarantees

- The root layout owns the document language, Geist font, metadata defaults, initial theme script, and keyboard skip link. Limit `suppressHydrationWarning` to `<html>`, whose `data-theme` may change before hydration.
- The workspace layout owns the shared Header and Footer for `/`, `/work`, and `/contact`. Auth examples use only the root layout. Route groups do not protect routes.
- Keep pages and layouts as Server Components. Header is a client boundary because it uses `usePathname`; ThemeToggle is a client boundary because it handles browser state. Do not mark the whole application as client-side.
- Keep site metadata and both navigation lists in `src/consts.ts`. Header and Footer derive the site name from `SITE`. Keep social URLs local to `GXB.tsx`.
- The theme defaults to dark and stores only `light` or `dark` under the `theme` key. Validate saved values before first paint, tolerate unavailable storage, and do not introduce a second theme system or system-preference behavior.
- Keep both Sun and Moon icons rendered so CSS controls their state without mounted-state guards. Preserve their contextual accessible labels and reduced-motion behavior.
- Keep `globals.css` focused on Tailwind, semantic document tokens, scrollbar color, background, foreground, and typography. Keep component-specific Tailwind classes with their components.
- Preserve the skip target and a descriptive heading on every page. The visually hidden workspace headings are intentional until visible page headings replace them.
- Preserve the seven local social icons, the supplied Vercel mark, and the favicon. Replace their sample branding only when the user asks or while adapting the generated project for an actual brand.
